# Donjons

Jeu de gestion : configure ton donjon (salles, pièges, monstres, garnison) pour le défendre en **raid PvP asynchrone**, et envoie une équipe de héros — personnalisés pièce par pièce via classe/sorts/talents/maîtrises obtenus au gacha, à la Pokémon — combattre en temps réel dans une **arène 2D façon Vampire Survivors** pour du loot, de l'équipement, du craft et des invocations gacha.

Stack : Next.js (App Router, TypeScript) · Tailwind CSS · Firebase (Auth + Firestore) · Vercel.

## Démarrage

```bash
npm install
cp .env.local.example .env.local   # puis remplis les valeurs (voir ci-dessous)
npm run dev
```

L'app tourne sur [http://localhost:3000](http://localhost:3000). Les pages se chargent sans Firebase configuré, mais toute action de jeu (connexion, héros, donjon...) a besoin des clés ci-dessous.

## Configurer Firebase

1. Va sur [console.firebase.google.com](https://console.firebase.google.com) et crée un nouveau projet (nom libre, ex. `donjons`).
2. **Authentication** → Sign-in method → active le fournisseur **Email/Password**.
3. **Firestore Database** → Créer une base → mode production → choisis une région proche.
4. **Règles Firestore** : onglet Règles de la base Firestore → colle le contenu de `firestore.rules` de ce repo → Publier. (Alternative en CLI : `firebase login && firebase init firestore && firebase deploy --only firestore:rules`.)
5. **Config web** : Paramètres du projet (⚙️) → Général → "Vos applications" → ajoute une app Web → copie les valeurs `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId` dans les variables `NEXT_PUBLIC_FIREBASE_*` de `.env.local`.
6. **Compte de service (Admin)** : Paramètres du projet → Comptes de service → "Générer une nouvelle clé privée" → télécharge le JSON. Reporte-le dans `.env.local` :
   - `FIREBASE_PROJECT_ID` = `project_id`
   - `FIREBASE_CLIENT_EMAIL` = `client_email`
   - `FIREBASE_PRIVATE_KEY` = `private_key`, **entre guillemets**, avec ses `\n` littéraux tels quels (attention si tu copies-colles depuis le JSON : n'inclus pas la virgule de fin de ligne du JSON, elle ferait partie de la valeur et casserait le parsing de la clé).

   Ce compte de service n'est utilisé que côté serveur (routes `app/api/**`), jamais exposé au navigateur.

**Première connexion** : tant que le profil n'a pas de `onboardedAt`, le jeu est remplacé par une introduction en 3 temps (`components/onboarding/Onboarding.tsx`) : le prologue « L'Astre brisé » (le lore : le Cœur-d'Étoile brisé par le Seigneur des ombres, les cristaux sont ses éclats, le joueur est un Gardien), une présentation du jeu en 5 cartes, puis le **choix du pseudo** (3 à 16 caractères, unique sans tenir compte des majuscules ni des accents, réservé dans la collection `displayNames`, route `POST /api/profile/onboarding`). On peut passer le prologue et la présentation, mais pas le choix du pseudo. Les textes sont dans `lib/game/content/lore.ts`. Les comptes créés avant cette fonctionnalité voient aussi l'introduction une fois.

La page de connexion propose « Mot de passe oublié ? » (email de réinitialisation Firebase, modèle par défaut activé avec le fournisseur Email/Password). Le tableau de bord affiche un guide « Premiers pas » (invocation → classe → sort → expédition → objet → donjon), calculé à partir des données existantes ; une fois terminé, il se replie en une ligne (toujours réouvrable).

Une fois `.env.local` rempli, relance `npm run dev` : l'inscription (`/inscription`) crée un compte, un profil Firestore, un unique héros de départ **sans classe** ("Recrue") et 15 cristaux d'invocation de départ. Un héros sans classe reste jouable partout (expéditions comprises) mais avec des stats volontairement très faibles, pour inciter à lui assigner une classe dès qu'elle est débloquée à l'invocation.

## Systèmes de jeu

- **Héros** (`/heros`) : un héros commence vide — sans classe, sans sort, sans talent, sans maîtrise — et devient ce que tu en fais. Tout se pioche à l'invocation puis s'équipe/se retire librement (rien n'est consommé à l'usage, comme un movepool Pokémon), avec un inventaire dédié (`/heros/inventaire`) qui liste tout ce qui a été obtenu :
  - **Classe** : remplace un rôle DPS/HEAL/TANK figé — 8 classes possibles (DPS : Guerrier/Archer/Mage/Assassin, soin : Prêtre/Druide, tank : Paladin/Colosse), rattachées à des stats de base + croissance par niveau (PV, attaques, défenses et vitesse ×1,5 par rapport aux premières versions). Change-la à tout moment (héros disponible requis) ; les points de talent déjà investis dans une classe restent en réserve et réapparaissent si tu la reprends plus tard. Simple débloqué/non-débloqué pour l'instant — pas de système de progression dédié (à venir séparément).
  - **Sorts** : de vrais sorts d'attaque (jusqu'à 2 équipés), 5 par classe (40), plus 6 sorts utilitaires de raid (Désamorçage / Éclaireur), la plupart avec un **élément** (voir plus bas), chacun avec **deux effets de combat distincts** — jamais un simple bonus de stats passif. Équipable sur n'importe quel héros, quelle que soit sa classe ; avoir la classe assortie au sort rend juste son effet plus fort (bonus de puissance sur les deux volets ci-dessous, pas une condition pour l'utiliser). En donjon (raid au tour par tour), le sort modifie l'attaque du héros : éclaboussure sur une cible proche, dégâts renforcés contre une cible affaiblie, perce-défense, étourdissement, vol de vie, poison, bouclier contre le prochain coup, ou (classes de soin) un soin renforcé à la place d'attaquer. En expédition (arène temps réel), le héros **lance automatiquement** chacun de ses sorts équipés avec un effet différent, adapté au temps réel, parmi 12 (3 à 5 sorts chacun) : onde de choc, salve de projectiles, soin de groupe, frénésie (cadence d'équipe), bénédiction (dégâts d'équipe), drain de vie, nova de givre (zone + ralentissement), arc électrique (rebondit sur 5 cibles), météore (zone sur le groupe le plus dense), égide (bouclier d'équipe), nuée toxique (poison de zone) ou coup de grâce (frappe le plus blessé). Sur la fiche du héros, les listes de sorts et de maîtrises se **filtrent** (recherche, élément, classe, effet en donjon/expédition, statistique, sans malus, équipés).
  - **Talents** : arbre à 4 paliers par classe (le 4e nécessite un rang d'étoile ≥3, 56 nœuds au total). Un nœud doit d'abord être obtenu au gacha (ou à l'Observatoire), puis s'active en y investissant des points de talent (1 par niveau gagné ; coût = palier). Il n'y a plus de prérequis entre nœuds : comme les nœuds tombent au hasard, un prérequis manquant bloquait le talent pour toujours. La fiche montre tout l'arbre de la classe, les nœuds non obtenus grisés.
  - **Maîtrises** : bonus passifs génériques (jusqu'à 3 équipées, 44 au total, dont des maîtrises de critique, de résistances élémentaires et de résistance aux pièges), non liés à une classe — plusieurs sont aussi des compromis bonus/malus (ex. + dégâts, − défense).
  - **Rang par doublon** : retirer un sort/talent/maîtrise déjà possédé au gacha ne redonne pas un doublon inerte — ça fait monter son rang (1 à 5, +8 %/rang sur son effet ; pour un sort, seul l'effet d'arène monte), jusqu'au rang max où il se reconvertit en jetons de rang. Les classes n'ont pas ce système (juste débloqué/non-débloqué).
  - **Ensembles** : sauvegarde nommée d'une combinaison classe + sorts + maîtrises, **commune à tous les héros du compte** (12 au plus) : on la sauvegarde depuis un héros et on l'applique à n'importe quel autre. Les anciens ensembles propres à chaque héros ont été repris dans la liste commune.
  - **Nom** : un héros se renomme depuis sa fiche (« ✎ Renommer », 2 à 20 caractères, pas d'unicité). La liste des héros montre l'équipement porté avec la couleur de sa rareté, et la fiche détaille chaque objet équipé. Le choix d'équipement ne liste que les objets libres (ou déjà portés par ce héros), triés par rareté et colorés selon elle ; qui porte quoi se voit dans l'atelier de la forge.
  - Emplacements de héros : 1 au départ, jusqu'à 12. Quand tous sont pris, le bouton **Recruter** achète d'abord un nouvel emplacement en or (150, puis ×1,5 à chaque emplacement), puis recrute un héros vierge.
- **Attaque/défense physique et magique** : les stats attaque et défense sont chacune scindées en physique et magique (`atkPhys`/`atkMag`/`defPhys`/`defMag`). Au combat, une unité frappe avec sa valeur dominante (phys. ou mag.) et l'adversaire mitige avec la défense correspondante — un guerrier tout en attaque physique perce mal une cible en défense magique, et inversement. Classes/talents/sorts/maîtrises/objets peuvent viser l'un, l'autre, ou un mix. L'attaque la plus faible des deux ne sert à rien : la fiche du héros indique l'attaque utilisée et l'explique.
- **Critiques et éléments** : chaque héros a un **taux de critique** (5 % de base, plus pour Archer/Assassin) et des **dégâts critiques** (+50 % de base), plafonnés à 75 % de chances. Il y a 5 éléments (🔥 feu, ❄️ glace, ⚡ foudre, ✨ sacré, 🌑 ombre) : le premier sort élémentaire équipé donne son **affinité** au héros, et toutes ses attaques portent cet élément, en arène comme en raid. Les monstres ont des résistances et des faiblesses (ex. le golem d'ossements craint le sacré et le feu mais encaisse l'ombre ; la liche frappe en ombre), et certains attaquent eux-mêmes avec un élément, réduit par les **résistances** du héros (maîtrises, affixes, talents défensifs). Plafond de résistance : 75 % ; une faiblesse peut aller jusqu'à doubler les dégâts. La page des expéditions affiche les éléments d'attaque et les faiblesses de chaque zone.
- **Invocation (gacha)** (`/gacha`) : dépense des cristaux 💎 pour tirer une classe, un sort, un talent, une maîtrise, de l'or, des jetons de rang ou des fragments de monstre. Système de pity (garantie de rareté après N tirages sans). **Garantie de première classe** : tant qu'un compte ne possède aucune classe, une classe tombe au plus tard au 10ᵉ tirage (les 15 cristaux de départ suffisent) — la classe reste gagnée au gacha, jamais offerte. Un doublon de classe déjà possédée, ou un sort/talent/maîtrise déjà au rang maximum, se reconvertit automatiquement en jetons de rang.
  - **Poussière d'étoile ✦ et Observatoire** : chaque tirage donne aussi de la poussière d'étoile (1 / 2 / 5 / 12 selon la rareté, et le triple pour un doublon déjà au maximum). À l'**Observatoire** (sur la page d'invocation), on l'échange contre l'élément **de son choix** : débloquer un élément pas encore obtenu (maîtrise 400, sort 800, talent 1 800, classe 6 000) ou monter d'un rang un élément possédé (maîtrise 80, sort 140, talent 220), ou encore 5 jetons de rang pour 60. Les taux du gacha ne changent pas : c'est une protection contre la malchance, sur le modèle du « spark » de Granblue ou de la boutique de Poussière d'astres de Genshin. En simulation, un héros principal complet (sa classe, ses 7 talents, 2 sorts et 3 maîtrises, tout au rang 5) demande environ 3 000 tirages (90 % des joueurs en moins de 3 600) ; toute la collection au maximum en demande environ 7 800.
  - **Obtenir des cristaux** : chaque expédition réussie (2 à 5 selon la zone, +1 si le boss est tué, +1 en Cauchemar/Tourment), la première victoire du jour dans chaque zone (+3, et 1 jeton de rang), le premier succès et le premier 3★ de chaque zone dans chaque difficulté (de 2 à 6, plus des jetons de rang), les raids (conquérir un donjon de joueur : 2 + 1 par tranche de 10 niveaux de défense, +2 s'il était au moins aussi fort que votre équipe, une fois par donjon et par jour ; +3 à +18 pour la première conquête d'un repaire selon son tier, puis +1), une défense réussie (+2, plus de l'or), et certains PNJ de la taverne.
- **Rang d'étoiles** (page détail d'un héros) : dépense jetons de rang + or pour monter un héros de 1★ à 5★ — augmente le cap de niveau, les stats, et débloque le talent de palier 4.
- **Expéditions** (`/expeditions`) : des sessions de 1 min 30 à 2 min (90 / 100 / 110 / 120 s selon la zone) dans une **arène 2D en temps réel** (`/expeditions/jouer/[id]`).
  - **Toute l'équipe est sur le terrain** : tu diriges le chef (ZQSD/WASD/flèches, ou clic/doigt maintenu), les autres le suivent en formation. Chaque héros a ses propres PV, attaque selon son rôle (DPS : tirs à distance ; Tank : frappe autour de lui et attire les monstres ; Soigneur : soigne le plus blessé, sinon tire) et lance ses sorts équipés en boucle. Les dégâts sont mitigés par la défense physique/magique, comme en raid. Un héros KO le reste jusqu'à la fin (sauf carte « Ralliement »).
  - **La puissance vient des héros** : classe, niveau, étoiles, talents, maîtrises, équipement et sorts (+ leurs rangs) définissent directement ce que fait chaque héros dans l'arène. Chaque zone affiche une **puissance conseillée**, comparée à celle de l'équipe choisie.
  - **Déroulé d'une partie** : vagues de monstres (orcs éclaireurs rapides, golems d'ossements lents et résistants, chamans orcs qui tirent à distance) et élites régulières, puis un **boss** 25 s avant la fin. **Les monstres se renforcent au fil de la partie** : chaque monstre qui apparaît a +60 % de PV et de dégâts par minute écoulée (le boss la moitié, en plus de ses propres multiplicateurs), et la taille des vagues plafonne à +6 (`timeRamp` / `MAX_WAVE_GROWTH` dans `lib/game/arena/engine.ts`). L'or, les ressources et l'XP des zones ont été multipliés par 2,5 avec l'allongement, et chaque partie fait **deux tirages d'objet** (mêmes chances de drop et de rareté qu'avant pour chacun). Le tuer termine la partie en victoire immédiate. Dans les trois premières zones, des **zones d'impact** (cercles rouges au sol, ~1 s d'alerte) tombent régulièrement sur l'équipe : 20 % des PV max en Lisière et Mines, 8 % en Ruines, rien en Nécropole, où les monstres suffisent. La défense ne les réduit pas (seule la carte Peau de pierre le fait) : rester immobile n'est donc jamais une stratégie, même avec un tank (`ZoneDefinition.hazard`).
  - **Montée de niveau en partie** : les monstres lâchent des gemmes d'XP. À chaque niveau, la partie se met en pause et propose **3 cartes** au choix (dégâts, cadence, PV, projectiles, perforation, critique, régénération… et des cartes « Maîtrise » qui renforcent les sorts présents dans l'équipe, chacune avec un bonus propre à l'effet : rayon, projectiles, rebonds, durée, seuil d'exécution…). Aucune carte ne porte le nom d'un talent ou d'un sort. Les bonus ne durent que la partie.
  - **Étoiles et progression** : ★ survivre, ★★ vaincre le boss, ★★★ vaincre le boss sans aucun héros KO. 4 zones en échelle (Lisière → Mines → Ruines → Nécropole), chacune débloquée en terminant la précédente. Premier succès et premier 3★ d'une zone donnent des cristaux bonus.
  - **Difficultés** : chaque zone se rejoue en 🟢 Normal, 🟡 Difficile, 🟠 Cauchemar et 🔴 Tourment (façon Diablo). Chaque niveau s'ouvre sur une zone après avoir battu son boss (2★) au niveau précédent. Les monstres y sont beaucoup plus forts (×2,8 / ×6,5 / ×12) ; en échange, l'or et les ressources augmentent (×1,5 / ×2,2 / ×3,2), l'XP aussi (×1,5 / ×2 / ×3), les objets trouvés montent jusqu'aux paliers 4 et 5 (stats et affixes plus forts), et il y a des cristaux en plus. **Les chances de butin et de rareté sont les mêmes à toutes les difficultés.** Étoiles et récompenses de première fois sont comptées séparément pour chaque difficulté.
  - **Butin** : or, ressources, jusqu'à deux objets (le premier garanti avec meilleure rareté si le boss est tué, le second au taux de drop normal), capture de monstre, cristaux, et XP pour chaque héros (réduite en cas d'échec). Tout dépend de la performance (étoiles, temps tenu, kills). Bouton **Rejouer** pour relancer la même équipe en un clic. L’équipe se compose à la main (le premier héros choisi, marqué 👑, est le chef) ou via « Équipe auto » (les plus forts) ; elle n’est plus pré-remplie, ce qui faisait partir d’autres héros que ceux cliqués.
- **Donjon** (`/donjon`) : configure une grille de salles (pièges/monstres/garnison de héros) sur une grille 5×5, avec un budget de points et un nombre de salles maximum limités par tes **améliorations** (voir ci-dessous). Le layout doit rester connecté à l'entrée (vérifié côté serveur). Les héros affectés en garnison passent en statut "en garde" et ne peuvent plus partir en expédition tant qu'ils y sont.
  - **Niveau de défense** : le niveau moyen de tes 4 meilleurs héros. Il multiplie les stats de tous tes monstres (×(1 + 0,45 par niveau au-dessus de 1), avant Maîtrise des bêtes) et ajoute 1 point de budget par tranche de 3 niveaux : ton donjon grandit avec toi. Il est recalculé à chaque attaque.
  - **Pièges** : 7 pièges, dont 5 élémentaires (runes 🔥, givre ❄️, foudre ⚡, glyphe ✨, voile 🌑). Un même piège ne peut être posé qu'une fois par salle, et chaque piège supplémentaire dans une salle frappe 20 % moins fort que le précédent. Leurs dégâts (un % des PV max) sont réduits par la **résistance aux pièges** des attaquants, par leur résistance à l'élément du piège et par un éventuel Désamorçage. Varier les éléments rend la préparation plus dure. **Les pièges usent, les monstres tuent** : un piège ne tue jamais (il laisse au moins 1 PV) et une salle piégée ne peut retirer plus de 28 % des PV max d'un héros (avant ses résistances). **Synergie pièges → monstres** : un héros qui perd au moins 8 % de ses PV max sur un piège gagne une charge « Affaibli » 💫 (2 au maximum) ; au combat suivant, chaque charge réduit ses dégâts de 20 % et augmente de 20 % ceux qu'il subit, puis le combat les efface. La résistance aux pièges et le Désamorçage évitent les charges. Un donjon mixte (pièges puis monstres) est ainsi le plus dur à préparer, sans qu'aucune préparation ne soit obligatoire.
  - **Monstres** : chacun a une faiblesse nette et une forte résistance (faiblesse de −40 %, résistance de 25 % au plus, 35 % pour la Liche : l'Orc éclaireur craint le feu et résiste à l'ombre ; le Golem d'ossements craint le sacré, résiste à l'ombre et à la glace ; l'Orc chaman frappe à la foudre et craint la glace ; la Liche frappe en ombre et craint le sacré). Frapper la bonne faiblesse change tout. On peut en empiler plusieurs du même type dans une salle (dans la limite des captures et de la Densité des dangers). Les 4 monstres se capturent en expédition (l'Orc éclaireur dans la Lisière).
  - **Journal de défense** : les 12 derniers raids subis (qui, quand, résultat, salle où l'attaquant est tombé, or perdu). Chaque attaque repoussée rapporte 2 💎 et de l'or selon le niveau de l'attaquant.
- **Améliorations** (`/donjon/ameliorations`) : dépense des ressources pour monter 8 filières indépendantes de ton donjon — Expansion (salles max), Architecture (budget de points), Vigueur défensive (taille et stats de la garnison), Ingénierie des pièges (tiers 2/3 débloqués aux niveaux 3/6, +5 % de dégâts des pièges par niveau), Maîtrise des bêtes (stats des monstres capturés en garde), Densité des dangers (occupants max par salle), **Coffre-fort** (−7 % de butin volé par niveau), **Sceaux élémentaires** (+4 % de résistance à tous les éléments par niveau pour les monstres et la garnison). Le coût de chaque niveau augmente (×1,35 par palier déjà atteint). Le budget total = Architecture + bonus du niveau de défense.
- **Raid PvP asynchrone** (`/donjon/attaquer`) : choisis une cible — le donjon d'un autre joueur, ou un **repaire pré-conçu par les développeurs** (5 tiers "bot" avec leur propre niveau de défense et un conseil de préparation, du Repaire des orcs au Sanctuaire piégé) — puis une équipe de **4 héros au plus** (`RAID_PARTY_MAX`), et explore la grille cible salle par salle (`/donjon/attaquer/raid`), sans jamais voir le layout complet à l'avance (brouillard de guerre : seules les salles visitées et leurs voisines immédiates sont révélées). Chaque salle atteinte peut contenir un piège (dégâts à toute l'équipe si une charge reste), des monstres/gardiens (combat au tour par tour, ciblage tank/soin), ou un trésor (butin mis en banque au fur et à mesure des salles atteintes). **Chaque salle au trésor ajoute du butin** : dans un repaire, chacune contient le butin complet du repaire ; chez un joueur, chacune contient une part de ce qui peut lui être volé plus un trésor créé (30 + 10 × niveau de défense en or, et 2 + 0,6 × niveau de chaque ressource), jamais retiré au défenseur (`treasureRoomBonus`, `DungeonRaid.bankedBonus`). Plus un donjon a de salles au trésor, plus il rapporte. Fuir à tout moment conserve le butin déjà banqué ; se faire anéantir (piège ou combat perdu) fait tout perdre (risque total, "all-or-nothing"). Contre un vrai joueur : une victoire ou une fuite débite le butin volé de son stock de ressources (le plafond d'or volé monte avec le niveau de défense) ; s'il repousse l'attaque, il reçoit 2 cristaux et de l'or. L'attaquant gagne des cristaux quand il conquiert un donjon (voir « Obtenir des cristaux »).
  - **Prime de conquête** : conquérir un donjon (toutes les salles au trésor) rapporte en plus un **objet** (cotes de rareté d'un boss d'expédition, palier 1 à 5 et stats selon le niveau de défense), des éclats de forge (3 + niveau/4) et, contre un joueur, de l'or (60 + 12 × niveau). Cette prime est créée, jamais retirée au défenseur ; elle est affichée sur chaque carte de cible. Le butin fixe des repaires a été multiplié par 4 (160 à 1 800 or).
  - **Liste des cibles** : 12 donjons de joueurs tirés au hasard autour de ton niveau (de −8 à +12), plus les repaires ; bouton « Nouvelles cibles » pour retirer. Chaque carte affiche un **rapport d'éclaireur** : niveau de défense, nombre de pièges et de monstres, garnison, éléments des dégâts et **faiblesses des monstres**, mais jamais le plan.
  - **Préparer son équipe** : en choisissant les héros, la page calcule ce que l'équipe apporte face à ce donjon (réduction des dégâts de pièges, soigneurs, éclaireur, résistances aux éléments menaçants, héros qui frappent une faiblesse). Leviers de préparation :
    - **Désamorçage** (sort de raid, maîtrisé par Assassin/Archer/Paladin) : −35 % de dégâts de pièges pour toute l'équipe (−50 % avec la classe assortie) ;
    - **Éclaireur** (Archer/Druide/Mage) : révèle le contenu des salles voisines, et leur nombre d'occupants avec la classe assortie ;
    - **Résistance aux pièges** : maîtrises (Pas feutré, Démineur, Armure matelassée, Instinct du pilleur), affixes (du Démineur, du Rôdeur), talents défensifs de l'Archer et de l'Assassin. Inutile en expédition : c'est un vrai choix de build ;
    - **Soins de marche** : chaque soigneur vivant soigne l'équipe de 6 % des PV max après chaque salle dangereuse (10 % s'il a un sort de soin) ; il ne retire pas les charges d'Affaibli ;
    - **Éléments** : l'affinité du héros contre les faiblesses des monstres, et les résistances contre les éléments des pièges et des monstres.
    Le premier sort équipé définit l'effet de raid : prendre Désamorçage ou Éclaireur, c'est renoncer à un effet de combat.
  - **Retour en arrière** : on peut revenir dans une salle déjà visitée voisine (un piège qui a encore des charges se redéclenche).
- **Forge** (`/forge`) : craft d'équipement (31 recettes sur 3 paliers : arme/armure/babiole, en physique ou magique, plus des bases critique, vitesse, résistances élémentaires ou résistance aux pièges ; filtres par emplacement et « Réalisables ») à partir de ressources récoltées en expédition. Chaque objet crafté (ou trouvé en expédition) tire une **rareté** (commun → légendaire, cotes dépendant du palier) qui augmente ses stats de base et fixe son nombre d'**affixes aléatoires** (0 à 3, parmi 24 lignes de bonus, dont critique et résistances élémentaires ; certaines sont des compromis bonus/malus, ex. + ATQ phys., − DEF phys.). Les objets trouvés dans les difficultés supérieures peuvent atteindre les paliers 4 et 5 ; les pourcentages (critique, résistances) progressent deux fois moins vite avec le palier que les stats fixes. Dans l'**atelier**, on peut ensuite :
  - **Améliorer** un objet de +1 à +10 (or + éclats de forge, +15 % par niveau sur ses stats positives, soit +150 % à +10 ; la carte de l'objet affiche chaque ligne avec sa valeur fixe puis sa valeur améliorée : « +14 ATQ mag. → +27 ATQ mag. ») : sans risque jusqu'à +5, puis chance de réussite décroissante — un échec consomme le coût mais ne rétrograde jamais l'objet. Fonctionne aussi sur un objet équipé.
  - **Réforger** (façon enchanteresse de Diablo III) : bouton ↻ sur **une** ligne d'affixe, qui est retirée ; les autres lignes, la base, la rareté et le niveau d'amélioration ne bougent pas, et la nouvelle ligne ne peut pas doubler une ligne gardée. Réforger la première ligne change le suffixe du nom.
  - **Recycler** toute une rareté d'un coup (bouton par rareté + confirmation affichant le nombre d'objets et le gain ; épargne les objets équipés et améliorés, `POST /api/items/salvage-bulk`), ou un objet non équipé : le détruit contre des **éclats de forge** (plus pour un objet rare, de haut palier ou amélioré) et un peu de la ressource de son emplacement (arme → minerai, armure → bois, babiole → essence).
- **Taverne** (`/taverne`) : un visiteur (PNJ) s'installe au comptoir et **change toutes les 30 minutes** (tirage propre à chaque joueur, jamais deux fois le même d'affilée ; certains sont rares ou légendaires et passent moins souvent). 59 PNJ en 4 types, dont 5 personnalisés (Loup Lune, Le Magnifique, Faucon, ZZ l'Éventreur, Dieu) :
  - **Marchands** : vendent ressources, éclats de forge, jetons de rang, cristaux ou objets (rareté parfois garantie) contre de l'or/des ressources — chaque offre une fois par visite.
  - **Conteurs** : racontent une histoire, paragraphe par paragraphe, sur le monde du jeu (zones, boss, classes…).
  - **Bienfaiteurs** : offrent une récompense gratuite, parfois au choix parmi plusieurs (un seul choix possible).
  - **Parieurs** : la mise est toujours payée, le gain n'arrive qu'en cas de victoire (chance affichée, tirée côté serveur).
  - Un **registre des visiteurs** garde la trace de tous les PNJ rencontrés (on peut y relire leurs histoires). La taverne ne donne jamais de classe/sort/talent/maîtrise : ça reste réservé au gacha.
- **Classement** (`/classement`) : 4 classements entre tous les joueurs, avec ta propre place même hors du top 50 :
  - **Puissance** : puissance cumulée de tes meilleurs héros (autant que la plus grande équipe d'expédition, soit 4).
  - **Expéditions** : total des meilleures étoiles par zone (départage : nombre de victoires).
  - **Raids** : 3 pts par donjon de joueur vaincu, 2 par attaque repoussée, 1 par repaire « bot » vaincu (départage : butin pillé aux joueurs). Compté à partir de l'ajout du classement (pas d'historique avant).
  - **Collection** : classes + sorts/talents/maîtrises débloqués (départage : rangs cumulés).
- **Le Velours Noir** (`/velours`) : mini-jeu de drague autonome, pour rire, dans un bar à hôtesses (contenu suggestif, fondu au noir, tous les personnages sont majeurs). Objectif : conquérir les 10 hôtesses, la dernière étant la patronne (Mama Lola), qui n'apparaît qu'après 9 conquêtes. Chaque nuit, 8 actions, 6 hôtesses en service (avec une humeur aléatoire) et +300 € de paie. À table : répondre à ses répliques avec un style (charme / humour / audace / sincère / flambe, chaque hôtesse a ses préférences), offrir un verre ou un cadeau (elle a un cadeau favori ; les cadeaux 🌶 offensent avant le palier Complice), ou tenter un geste osé (gros gain ou gifle). Les paliers 40 / 70 débloquent des scènes, à 100 on propose un after (la conquête). Aucun lien avec l'économie du jeu : sauvegarde en `localStorage` uniquement. Sprites générés depuis le PSD « Anime Mature Woman » de Sutemo (4 expressions dans sa tenue normale, puis les mêmes dans sa tenue « osée », qu'elle garde une fois la scène du palier 70 vue). Les scènes déjà débloquées se revoient à sa table (« Souvenirs »).

## Architecture de jeu

- Tout ce qui modifie l'économie (or, cristaux, XP, loot, combat, craft, gacha) passe par des routes API serveur (`app/api/**/route.ts`) qui utilisent `firebase-admin` — le client ne peut qu'écouter ses propres données en lecture (`onSnapshot`), jamais écrire directement dans Firestore. Voir `firestore.rules`.
- Règles d'écriture côté serveur : Firestore admin est configuré avec `ignoreUndefinedProperties` (`lib/firebase/admin.ts`) car beaucoup de champs de jeu sont optionnels. Tout ce qui paie (réclamation d'expédition, chaque pas de raid via `commitRaidStep`) relit son document dans la transaction pour qu'un double clic ou deux onglets ne paient jamais deux fois. À chaque connexion, `/api/bootstrap` répare aussi les références orphelines (objet porté par un héros supprimé, héros bloqué « en expédition »/« en raid » sans partie active).
- Le contenu de jeu (classes, sorts, talents, maîtrises, salles/pièges/monstres, donjons "bot", filières d'amélioration, zones de farm, recettes de craft, affixes d'objets, table de gacha) est défini dans `lib/game/content/*.ts` — pas en base de données. Pour ajouter du contenu (une classe, un sort, une zone, une recette...), c'est le seul endroit à éditer. Les ensembles sont sur le profil (`UserProfile.builds`, voir `lib/game/builds.ts`) ; tant qu'il est absent, la liste est l'union des anciens `Hero.builds`, qui ne sont jamais effacés. Les composants de héros (classes/sorts/talents/maîtrises) sont piochés au gacha : `UserProfile.unlockedClasses` (classes, simple liste) et `UserProfile.componentRanks` (sorts/talents/maîtrises, id → rang 1-5) puis équipés librement sur n'importe quel héros (`Hero.equippedSpellIds`/`equippedMasteryIds`/`talents`) — rien n'est consommé à l'équipement, voir `lib/game/engine/stats.ts` (`resolveHeroStats` prend le compte des rangs en 3ᵉ argument pour scaler chaque bonus).
- Le raid de donjon (`lib/game/engine/dungeonRaid.ts` + `dungeonCombat.ts` + `dungeonLayout.ts`) résout chaque déplacement de salle indépendamment côté serveur, avec un RNG seedé (mulberry32, `lib/game/engine/rng.ts`) dérivé du raid et de la position ciblée — déterministe et rejouable salle par salle (mais plus un seul replay global comme l'ancien système). Le layout complet du donjon défenseur n'est jamais envoyé au client : les routes `app/api/dungeon/raid/**` ne renvoient qu'une vue filtrée (`RaidView`) des salles visitées + les salles adjacentes non révélées, et le document Firestore `dungeonRaids/{raidId}` a une règle `read: false` inconditionnelle (même pour son propriétaire) — l'état brut du raid ne quitte jamais le serveur.
- Les règles d'objets (tirage rareté/affixes, amélioration, réforge, recyclage) sont dans `lib/game/engine/items.ts`, sans import serveur, pour que la forge et les routes `app/api/items/[id]/{enhance,reforge,salvage}` calculent les mêmes coûts. Un objet stocke ses valeurs d'affixes tirées (`Item.affixes`) : rééquilibrer `lib/game/content/affixes.ts` ne modifie pas les objets existants. Les stats totales d'un objet passent par `itemTotalStats` (utilisé par `resolveHeroStats`). La réforge (`POST /api/items/[id]/reforge`, `{ affixIndex }` obligatoire) ne retire qu'une ligne ; un appel sans `affixIndex` (onglet resté sur l'ancienne forge) est refusé au lieu de tout retirer. La prime de conquête des raids (`rollConquestBounty` / `conquestBountyPreview` dans `lib/game/engine/loot.ts`) est payée dans `commitRaidStep`, qui renvoie `{ crystals, bounty }` ; la route de déplacement la renvoie dans `RaidView.bounty`.
- Le mini-jeu d'arène (`lib/game/arena/engine.ts`) tourne côté client en temps réel (boucle `requestAnimationFrame`). Le calendrier d'apparition des monstres ne dépend que du temps (`waveSize`/`maxKillsUntil`) : la route `app/api/expeditions/claim` s'en sert pour borner les kills rapportés, refuse une durée supérieure au temps réel écoulé, et ne valide le boss que s'il avait eu le temps d'apparaître. Un client modifié pourrait encore tricher dans ces limites, ce qui reste acceptable pour un projet perso. Progression par zone et par difficulté : `UserProfile.expeditionRecords`, dont la clé est l'id de la zone pour Normal et `zoneId:difficulté` sinon (`recordKey` dans `lib/game/content/difficulties.ts`) ; le bonus quotidien est noté sur la fiche Normal (`dailyBonusDay`). `zoneAtDifficulty` construit la zone mise à l'échelle, utilisée à la fois par l'arène côté client et par la route de réclamation. `Expedition.difficulty` est absent sur les anciennes expéditions (= Normal).
- Le combat de raid (`lib/game/engine/dungeonCombat.ts`) résout les dégâts par type : une unité attaque avec sa plus haute valeur entre `atkPhys`/`atkMag`, mitigée par la `defPhys`/`defMag` correspondante de la cible. L'arène utilise la même logique (attaque dominante, mitigation par la défense correspondante), avec un plancher de dégâts pour rester fluide en temps réel. Les règles de critique et d'élément sont partagées dans `lib/game/engine/elements.ts` (`critChance`, `critMultiplier`, `elementalMultiplier`, ainsi que les listes de clés de stats `STAT_KEYS`, `FLAT_STAT_KEYS` et `PERCENT_STAT_KEYS`). L'affinité d'un héros vient de `heroElement` (`lib/game/engine/stats.ts`). Les monstres portent leurs résistances dans `stats` et leur élément d'attaque dans `MonsterDefinition.element`. Le rang d'étoiles ne multiplie que les stats fixes, pas les pourcentages.
- Stratégie de raid : `dungeonIntel` (`lib/game/dungeonIntel.ts`) produit le rapport d'éclaireur de la liste des cibles (`app/api/dungeon/targets`, tirage aléatoire autour du niveau via `Dungeon.defenseLevel`, élargi si trop peu de résultats). `resolveTrapTrigger` applique l'atténuation de l'empilement (`TRAP_STACK_FALLOFF`), `trapRes`, l'élément du piège et l'aura `partyDisarm` ; `resolveMarchHeal` gère les soins entre les salles ; `toRaidView` révèle les salles voisines quand un héros vivant a le tag `scout`. `monsterScaleForDefenseLevel` (`lib/game/content/dungeon.ts`) et `dungeonPointBudget` / `dungeonDefenseLevel` (`lib/game/content/dungeonUpgrades.ts`) règlent la montée en puissance des défenses ; la route de démarrage de raid recalcule le niveau de défense à partir des héros du défenseur. Le journal de défense (`UserProfile.defenseLog`) et le « une conquête payée par jour » (`UserProfile.raidConquests`) sont écrits dans `commitRaidStep`.
- Le sort équipé d'un héros donne son `raidEffectTag` (`SpellDefinition`) au combat de raid : au tour de ce héros, `dungeonCombat.ts` applique l'effet (éclaboussure, dégâts renforcés, perce-défense, étourdissement — état `Set`/`Map` local à la salle qui persiste entre les rounds —, vol de vie, bouclier, ou soin renforcé pour les classes de soin) au lieu d'une attaque neutre. Un héros de garnison hérite du même effet via son sort équipé (`lib/game/engine/dungeonRaid.ts` `GarrisonMember.raidEffectTag`) ; les monstres n'ont pas de sort, donc pas d'effet. Le même sort donne un `arenaAbilityTag` différent pour l'arène : chaque héros lance chacun de ses sorts équipés sur un temps de recharge (`ARENA_SPELL_TAGS`), avec une puissance augmentée par la classe assortie et le rang du sort.
- La taverne (`lib/game/tavern.ts`, contenu dans `lib/game/content/tavern.ts`) est déterministe : le PNJ du moment se déduit de l'`uid` + du créneau de 30 min (`currentTavernSlot`), donc la page le calcule sans appel serveur. `POST /api/tavern/visit` l'inscrit au registre ; `POST /api/tavern/interact` recalcule le même PNJ côté serveur, refuse un créneau expiré et applique coût/récompense en transaction. État par profil : `UserProfile.tavern` (créneau courant, offres prises, PNJ rencontrés) — les offres prises repartent à zéro à chaque nouveau créneau.
- L'Observatoire : prix et gains de poussière dans `lib/game/content/observatory.ts`. La poussière est calculée par tirage dans `performPulls` (`GachaPullResult.stardust`) et stockée dans `UserProfile.stardust` ; les achats passent par `POST /api/gacha/observatory` (UI : `components/gacha/Observatory.tsx`). Les cristaux de raid sont versés dans `commitRaidStep`, qui renvoie le montant ; la route de déplacement le renvoie dans `RaidView.crystalsEarned`, et `UserProfile.botDungeonWins` sert au bonus de première conquête.
- Le classement (`lib/game/leaderboard.ts`, `GET /api/leaderboard`) est recalculé côté serveur à partir des profils, héros et objets équipés de tous les joueurs, avec un cache mémoire d'une minute — rien n'est dénormalisé, sauf les compteurs de raid (`UserProfile.raidStats`), incrémentés dans `commitRaidStep` (`lib/game/dungeonRaidLifecycle.ts`). Ce calcul « tout lire » convient à quelques dizaines de joueurs ; au-delà, il faudra stocker les scores.
- Le Velours Noir (`lib/velours/content.ts` pour les hôtesses, répliques, cadeaux et scènes, `lib/velours/engine.ts` pour les règles, `components/velours/VeloursGame.tsx` pour l'interface) est volontairement isolé : 100 % client, aucune route API, aucune donnée Firestore, sauvegarde `localStorage` (`velours-noir-save-v1`). Les sprites (`public/velours/<id>/*.png`) sont générés par `scripts/velours-sprites/build.mjs` à partir de `assets/Anime Mature Woman Free.psd` (coiffure, tenue, teinte et expressions par fille dans la table `H`).

## Déploiement (Vercel)

1. Sur [vercel.com/new](https://vercel.com/new), importe le repo GitHub `RyroyNotFound/Donjons` (framework détecté : Next.js, aucun réglage à changer — `vercel.json` n'est pas requis).
2. Avant de cliquer *Deploy*, ouvre **Environment Variables** et ajoute les 9 variables de `.env.local` (Production + Preview) :
   - les 6 `NEXT_PUBLIC_FIREBASE_*` ;
   - `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`.
   - Pour `FIREBASE_PRIVATE_KEY` : colle la valeur **sans les guillemets englobants ni la virgule finale** (de `-----BEGIN PRIVATE KEY-----` jusqu'à `-----END PRIVATE KEY-----\n`). Les `\n` littéraux conviennent, le code les convertit.
3. Déploie. Chaque push sur `main` redéploie ensuite automatiquement (les autres branches donnent des URL de Preview).
4. Console Firebase > **Authentication > Paramètres > Domaines autorisés** : ajoute le domaine Vercel (`<projet>.vercel.app`), sinon la connexion échoue en production avec `auth/unauthorized-domain`.
5. Si une variable d'env change plus tard : modifie-la dans Vercel puis **Redeploy** (les `NEXT_PUBLIC_*` sont figées au moment du build).
